# System Architecture Overview

사용자는 UI, Python API, CLI, 또는 AI Agent를 통해 Aerospike CE Ecosystem을 사용합니다. 실행 환경은 ACKO가 관리하는 **Kubernetes**와 client가 직접 연결하는 **Bare Metal** 경로로 나뉩니다.

## 계층 구조

### 1. User → Agent → Plugin

사용자는 도구를 직접 실행하거나 AI Agent에 작업을 요청할 수 있습니다. Plugin은 Agent가 올바른 절차와 API를 선택하도록 안내하지만, 별도의 Agent를 실행하지는 않습니다.

| 계층 | 설명 |
|------|------|
| **User** | 개발자, DevOps 엔지니어 |
| **Agent** | Claude Code, claude-code-action 등 AI 에이전트 |
| **Plugin** | 9개 Skill (별도 Agent 없음)로 ACKO 배포, aerospike-py API 가이드 제공 |

### 2. Kubernetes 배포 경로

Kubernetes에서는 ACKO가 `AerospikeCluster` CR을 읽고 필요한 리소스를 선언적으로 관리합니다.

1. 사용자가 `kubectl apply -f ascluster.yaml`을 실행하거나 Cluster Manager UI에서 CR을 만듭니다.
2. ACKO가 CR을 감지하고 StatefulSet, Service, ConfigMap 등을 생성합니다.
3. Aerospike CE Pod가 rack-aware 구성으로 배치되고 metrics exporter가 함께 동작합니다.

Cluster Manager는 Kubernetes 안에서 실행할 수 있습니다. Backend는 aerospike-py로 Aerospike data에 접근하고 Kubernetes API로 ACKO 리소스를 관리합니다.

### 3. Bare Metal 배포 경로

Kubernetes를 사용하지 않는 환경에서는 application이 aerospike-py로 Aerospike node에 직접 연결합니다.

1. aerospike-py가 Aerospike protocol로 seed node에 연결합니다.
2. Cluster는 물리 server에 설치된 Aerospike node와 rack 구성으로 동작합니다.

| 관계 | 설명 |
|------|------|
| Cluster Manager → aerospike-py | Backend가 aerospike-py를 사용해 Aerospike data를 읽고 씁니다. |
| Cluster Manager → ACKO | Kubernetes API를 통해 ACKO가 관리하는 cluster를 조회하고 변경합니다. |
| ACKO → Aerospike CE | StatefulSet과 관련 리소스로 Aerospike Pod의 lifecycle을 관리합니다. |
| aerospike-py → Aerospike CE | Kubernetes와 Bare Metal 환경 모두에서 Aerospike protocol로 직접 연결합니다. |
| Plugin → ACKO, aerospike-py | Claude Code Skill이 배포 절차와 API 사용법을 안내합니다. |

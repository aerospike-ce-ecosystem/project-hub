# 2026년 3월 의사결정 로그

이 문서는 2026년 3월에 내린 주요 의사결정과 그 배경을 날짜순으로 정리합니다. 세부 검토 내용이 있는 항목은 관련 ADR과 PR을 함께 연결합니다.

## 2026-03-15 | Agentic Workflow 도구 전환

**결정**: Agentic Workflow 도구를 `gh aw`에서 `claude-code-action`으로 전환했습니다.

- **배경**: 기존 `gh aw` 기반 workflow에서 통합과 확장에 제약이 있었습니다.
- **근거**: `claude-code-action`이 Claude Code ecosystem과 더 자연스럽게 통합되며 확장하기도 쉬웠습니다.
- **참조**: ADR-0008 (IssueOps CI Workflow)

## 2026-03-25 | DaisyUI 제거 및 Pure Tailwind CSS 4 전환

**결정**: Cluster Manager에서 DaisyUI를 제거하고 Pure Tailwind CSS 4와 Radix UI로 전환했습니다.

- **배경**: DaisyUI의 opinionated style이 custom design system을 구축하는 데 제약이 됐습니다.
- **근거**: Tailwind CSS 4의 utility-first 방식과 Radix UI의 accessible headless component를 조합하면 UI를 더 유연하게 설계할 수 있습니다.
- **영향**: PR #153에서 Radix 기반 primitive component 14개를 구현했습니다.
- **참조**: [ADR-0005: DaisyUI Removal](../../architecture/adr/2026-02-25-daisyui-removal.md)

---

## 2026-03-26 | aerospike-py v0.0.4 Unified BatchRecords API

**결정**: 모든 batch operation의 반환 type을 `BatchRecords` NamedTuple로 통일했습니다.

- **배경**: `batch_read`, `batch_write`, `batch_operate`가 서로 다른 type을 반환해 API를 일관되게 사용하기 어려웠습니다.
- **근거**: per-record `result_code`와 `succeeded`/`failed` count를 제공하면 모든 batch operation에서 같은 방식으로 error를 처리할 수 있습니다.
- **참조**: [ADR-0009: Unified BatchRecords API](../../architecture/adr/2026-03-20-unified-batch-records-api.md), PR #239

---

## 2026-03-28 | Cluster Manager OOM 방지 및 대용량 데이터 안정성

**결정**: Record Browser의 limit, pagination, timeout 제어를 강화했습니다.

- **배경**: 대용량 set을 탐색할 때 browser에서 OOM이 발생할 수 있었습니다.
- **근거**: scan 결과를 1,000 records로 제한하고 pagination과 backend timeout을 적용해 memory 사용량을 제어했습니다.
- **영향**: PR #152

## 2026-03-29 | project-hub 레포 생성

**결정**: cross-repo 프로젝트를 관리하기 위한 `project-hub` repository를 만들었습니다.

- **배경**: 프로젝트 현황, release, roadmap 등 에코시스템 전체 정보를 한곳에서 관리할 공간이 필요했습니다.
- **구현**: Docusaurus 기반 documentation site로 구축했습니다.
- **범위**: release matrix, changelog, decision log, roadmap, project goals를 포함합니다.

## 2026-03-29 | ReactFlow 인터랙티브 아키텍처 다이어그램

**결정**: `@xyflow/react` 기반 interactive architecture diagram을 도입했습니다.

- **배경**: 정적인 Mermaid diagram만으로는 복잡한 module dependency를 탐색하기 어려웠습니다.
- **구현**: Ecosystem, aerospike-py, ACKO, Cluster Manager, Plugins를 위한 ReactFlow component 다섯 개를 만들었습니다.
- **장점**: node 이동과 zoom을 지원하며, node를 클릭해 GitHub로 이동하거나 MiniMap으로 전체 구조를 탐색할 수 있습니다.
